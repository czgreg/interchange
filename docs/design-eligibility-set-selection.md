# 设计：资格集选择（Eligibility-Set Selection）

状态：**五方第一性原理联合推演后的共识方案。生产未改动一行。**
日期：2026-08-31
方法：5 个独立视角（目标/信号/机制/控制论/对抗-迁移）各自从零推演，
本文是收敛结果 + 收敛者对两处张力的裁决。
前序：`design-pool-sizing-rejected-v1v2.md`（v1 相对带、v2 绝对门，均被否）。

---

## 0. 五方一致的核心结论（无异议）

**"选固定 K 个成员组成池"这个抽象本身是病根，删掉它。**

1. **K 不是需求，是意外**（目标 agent）。它从一个三输入全未实测的容量
   公式掉出来（`t_active=50` vs 实测 19；`cap_per_node=10` 从未测）。真实
   需求是一个 **[下限, 上限] 区间**：够冗余、不过量暴露检测面——不是目标
   整数。
2. **强制固定大小 = 无死区的比较器驱动饱和执行器**（控制论 agent）。实测
   loop 周期恰好 300s，49 次 transition 里 15 次是纯周期-2 反转,系统在
   执行器自己的节拍上极限环振荡。信号 SNR ≈ 0.02–0.05（真实档差 25–80,
   composite 噪声 1400–4500），`swap_threshold=100` 在噪声底下 15–45 倍。
3. **K 唯一的作用就是"HRW 从哪个集合里选"**（机制 agent）。它不是容量
   预留、不是负载均衡(负载均衡是 HRW 做的,实测每节点最多 6 终端 vs
   cap 10)。删掉固定大小,改成 **HRW 在"全部合格节点"上跑**,可抢的边缘
   槽从构造上消失,乒乓随之消失。
4. **反检测上还更优**（机制 agent，用出厂 hash 在真实 /24 上实测）：固定 K
   换槽动 **24%** 终端出口(因为逼着"删+增"同时发生),eligibility-HRW
   只付实际发生的那一半(降级只走=14.6%,恢复只加=10.6%)。
5. **liveness 归 mihomo,不归 scorer**（控制论 + 对抗 agent）。mihomo 的
   `load-balance` + health-check(30s)已在 ~30–90s 内为新流跳过死节点。
   scorer 只该管"数十分钟尺度的慢速质量",别再抢着做快决策。

## 1. 目标函数与不变量（目标 agent，五方采纳）

> **最大化"被固定到真实质量好的出口的终端数",同时最小化"每终端每天
> 出口 IP 变更次数",硬约束:(i) 绝不把终端困在死出口;(ii) 扛住任一
> 单节点故障。**

两个目标本身冲突。现在系统用噪声信号狂追质量,把稳定性(反检测)砸了
——每次换槽 13–24% 终端换 IP,~50 次/天。

不变量(与机制无关,任何设计都要满足):

| # | 不变量 | 来源 |
|---|---|---|
| I1 | 无故障时,终端出口 IP 不变 | `config.go:279-285` 反检测 |
| I2 | 每终端每天 IP 漂移有上限 | `config.go:917-926` |
| I3 | 绝不困在死出口,failover 要快 | `perterminal.go:6-8` |
| I4 | 扛单节点故障:每终端 ≥2 个 alive 可选,实践中合格集 ≥3–4 个不同节点 | `config.go:636-639` |
| I5 | 选择由**真实目的地质量**驱动,非代理指标 | ρ(gstatic,真实)=−0.26 |
| I6 | 合格要过一道**绝对可达性底线**(到不了必需目的地=不合格),与相对排序分开 | live: BGP_E 到 Google 坏却在池 |
| I7 | 检测面上限:对单一目的地呈现的出口 IP 数留在"小企业 NAT"带 | `config.go:640-644` |

## 2. 收敛者裁决:两处张力（我作为收敛者定,不含糊）

五方在架构上无冲突,但有两处看似矛盾,其实是各自没看到对方的信息。我裁决:

### 张力 A:绝对门 vs 相对门(目标 I6 要绝对,控制论要相对)
**裁决:两者都要,但作用于不同的轴,不是二选一。**
- **可达性(liveness/成功)轴 → 绝对 + 差分**。"到不了必需目的地"是绝对
  事实,该判不合格(I6)。但**整池相关退化时不能绝对**(会清空集合=v1
  死因)。解法(控制论 agent):绝对门只对"**差分性死亡**"的节点生效
  ——它的同订阅同侪都好、只有它坏。整个订阅一起慢 = 供应问题,报警 +
  `supply_limited`,**不逐个剔**。
- **延迟排序轴 → 相对**。好节点之间(实测 7 个可替换,档差 25–80)按相对
  排序 + 强 incumbency,别每轮重排。

### 张力 B:要不要换新信号(信号 agent 说被动能分开好坏 / 对抗 agent 说砍掉信号项目)
**裁决:核心方案不依赖任何新信号;新信号是可选的、必须先实测证明的后续增量。**
- 我亲自核实了信号 agent 的支点数字:**"BGP_D 44% 真失败"在我的快照里
  不复现**(此刻 BGP_D 仅 2 连接;全队最高小包关闭是 BGP_E 12.1%),而且
  被动统计现在**只按节点聚合、不按目的地**(`passive.go:20`),"按目的地
  拆"是要写新代码的提案。样本量小(每节点 2–33 连接)、有误报(浏览器
  预连接也小包关闭)。
- **这与 v1/v2 的死因同类:在一个快照上成立、换个时刻不复现。** 所以我
  **不把方案核心押在它上面**。它进入"后续增量"(§5),上线前必须影子实测
  证明其区分力稳定、可复现,才允许接入排序/门。

**结论:核心方案是纯结构性的——删固定 K + eligibility-HRW + 现有信号 +
控制论加固,不需要任何未验证的新信号。** 这正是对抗 agent 说的"诚实
地板",也是五方去掉分歧后剩下的硬共识。

## 3. 方案(简化裁决后 —— 近乎纯删除)

> **两 fork 简化对冲的裁决**:eligibility-HRW 只从构造上消除了"节点间
> 抢固定槽"(inter-node),没消除"单节点在门槛附近抖"(intra-node)。但
> 关键事实:**合格集不需要新建 RTT/质量门——现有 `Qualified` 门
> (`scorer.go:1210-1265`)已经是"活着且可达",抗噪基于"最近 5 探针成功
> 计数"(要 5 个全失败才掉),不是 ±1400-4500 的 composite。** 于是守门
> fork 担心的"近门槛抖动"在"资格=liveness 门"下基本不成立——掉出是"要
> 彻底不可达"这种很黏的条件,不是刀刃。故从旧架构继承的整套控制论加固
> (Schmitt 死区 / dwell / incumbency 主决策层 / 差分算法 / EWMA 重调)
> 全部 CUT,只留一处真幸存的:min_pool 填充稳定性。

### 3.1 结构:删固定 K,改 eligibility-set HRW(核心,近乎纯删除)
- **删除**:fill 后处理"无条件填满到 kTarget"块(`scorer.go:799-826`)、
  preferredSet top-K 排序切(`:650-667`)、fast-evict(`:704-722`)、
  swap_threshold 门(`:728-744`)、poolFillCeiling、computeK 的"目标"语义。
- 合格集 `E = Qualified(node) ∩ !inQuarantine ∩ (!inTrial || 已在池内)`。
  - `Qualified` = **现有 `scoreNode` 门原样不动**:5-探针成功平滑
    (`recentOk`,`scorer.go:1234`)+ catastrophic `fail_rate≥0.9`
    (`:1262`)。即"活着且可达,自带 ~2.5min 抗噪"。
  - `!inQuarantine`(`:656`)、`!inTrial||已在池`(`:664`)两个现有过滤
    **必须留**:否则 rollback 隔离下一轮被推翻 / 新节点一轮幸运扫入。
- 唯一"接线"改动:`routingMembers = E`,喂给 `perTerminalMembers`,而非
  top-K(`scorer.go:1079-1085`)。`fb-<ip>=hrwTopN(ip,E,2)`,`perterminal.go`
  完全不动。
- **K 只以"下限"存活**:`min_pool_size = 3`(低于 2 时 per-terminal top-2
  静默失效退化成裸 `MATCH,us-pool`,`perterminal.go:83,108` → consistent-
  hashing 按目的地把单终端流量拆到多节点,违反单出口不变量)。`|E| < 3`
  时从 best-by-EWMA 补到 3,**且粘住在位填充者**(现有网 `scorer.go:837-863`
  每轮按 EWMA 重挑,floor-bound 时会在下限内造 mini 乒乓——这是守门 fork
  唯一真正幸存的点,必须加填充稳定性)。`k_max` 留作宽松安全阀(不 tune)。

### 3.2 资格门:就用现有 liveness 门,不新建(简化裁决)
**不新建双轴门、不新建 RTT 门、不加 Schmitt/dwell/incumbency。** 理由:
- 资格 = 现有 liveness 门,抗噪已由"5 探针要全失败才掉"提供(黏,非刀刃)。
- **不做相对质量门**——正是 v1(相对带掩盖相关退化)和 v2(绝对 composite
  门误杀健康节点)的死因;liveness 绝对门 + 不排序,天然规避两者。
- **incumbency 主决策层 CUT**:纯门谓词天然位置无关,在位/挑战者同信号
  同待遇,无"重排"要抑制。
- **差分共模算法 CUT**:见 §3.3——"不塌空、不掩盖"的结果由 liveness门 +
  保命网 + 告警交付,不需要专门的差分算法。

### 3.3 相关退化:靠 liveness门+保命网+告警,不靠差分算法(简化裁决)
整池相关退化是本 fleet 主要真实故障(实测 5 Hutao 里 3 个 alive=false、
p95 4400+)。三件现成的东西合起来就是答案,无需新机制:
- **liveness 门是绝对可达性、不是相对质量**:整片变慢但可达 → 谁都不剔、
  继续服务(v1 相对门会掩盖,这里天然不掩盖)。
- **整片真不可达 → 掉到 min_pool 下限**:保命网从 best-by-EWMA 托住 ≥3
  个(即便都超时),保住单出口不变量、降级但不空。
- **告警**:合格数贴近 min_pool、或在池 not-alive 数 ≥N 时触发。**需先接
  Lark webhook(当前为空)**。这是唯一要新增的"相关退化"逻辑。
- 已知残余风险(交影子模式测):`recentOk==0` 门在 gstatic **相关性抖动**
  下可能让整片 cohort 掉到 floor 再回来,造成重映射。**若**影子测出,
  **才**加迟滞,且最小形式 = **非对称:慢删(N 轮连续失败)、快加**(快
  failover 由 mihomo secondary 兜)。不投机预建。

### 3.4 前置硬修复(独立真 bug,迁移阻断级)
- **`poolSet` 重启恢复**(对抗 agent 升级为硬阻断):`loadState`
  (`persist.go:62-101`)不恢复 `poolSet`,每次重启走 bootstrap 无护栏路径、
  绕过刚加的迟滞。冷启用当前信号新算,不信盘上陈旧 `strikes`(现网死节点
  strikes 高达 11959)。**必须先于 §3.1/§3.2 上线并单独验证。**
- **fill-skip bug**:`scorer.go:808` 只跳 `newPoolSet||evicted`,swap-gate
  拒绝的节点两者都不在→同轮被回填。删 fill 时一并消除。
- **接 Lark webhook**:`webhook_url:""`,当前无任何告警通道。§3.3 依赖它。
- **`cp /usr/local/bin/leap-gateway{,.bak-preship}`**:prod 二进制 mtime
  比 HEAD 早 33min、Makefile 烤了版本串没法 bit 级重建,**这个备份是唯一
  回滚物**,零成本,上线前必做。

### 3.5 观测 + 灰度
- `/api/status` 增 `in_eligible_count`、`pool_size`;`supply_limited` 重定义
  为 `in_eligible_count < min_pool_size`。修 `"qualified"` 字段(现在数
  `InPool`,真值 `tier1_count`)。
- `node_qualify.sizing_mode: eligibility | legacy`,默认 legacy,**显式枚举
  校验**、非法值 fail-closed 到 legacy(yaml 非严格解析,打错字会静默跑错)。
  仅在 `case "auto"` 内切(manual + emergency_promote_chain 不受影响)。
- 合格集必须继承现有 `!inQuarantine && (!inTrial || currentlyInPool)`
  过滤(`scorer.go:655-668`),否则 rollback 隔离被下一轮推翻。
- **`legacy` 分支在 eligibility 验证通过后删除**——不长期养两个 sizer。

## 4. 能兑现什么 / 不能兑现什么(诚实边界)

**能(核心方案,现有信号即可):**
- 乒乓消失:删固定 K → 无边缘槽可抢(结构性,非调参)。
- 稳定收敛:合格集大小 = 当前合格节点数,自动伸缩,不发版、不手挑。
- 反检测改善:每终端 IP 变更从 ~50/天噪声驱动,降到只在真实质量/liveness
  穿越时发生,且每次更便宜(单边 10–15% 而非双边 24%)。
- hard-down failover:mihomo 30–90s(本来就有,不归 scorer)。
- **差分死亡的慢节点**会被可达性轴剔除(数十分钟尺度)。

**不能(诚实,别重蹈 v1/v2 过度承诺):**
- **"几分钟内自愈"做不到**(控制论:噪声自相关时间是分钟级,快于此必然
  重造乒乓)。质量剔除的可靠最快是 **~20–40min**。这对慢速质量足够,
  hard-down 另有 mihomo 兜。
- **"按目的地精细识别活着但慢的节点"**(如 BGP_E 那条 accounts.google
  5–9s 腿)**核心方案不做**——需要新信号(§5),且我实测其当前区分力不
  可复现,未证明前不接入。

## 7. 五方落点存档
- **无异议共识**:删固定 K(病根)、eligibility-HRW、liveness 归 mihomo、
  poolSet 恢复 / TTL / flag+shadow / min_pool≥2 是独立真修复。
- **收敛者裁决**:(A) 绝对门只对差分死亡 + 相对排序管好节点之间——双轴,
  非二选一;(B) 核心方案零新信号,新信号是须先实测的后续增量(我实测
  信号 agent 的支点数字不可复现,故不押核心于它)。
- **两轮前被否**:v1 相对带(对相关退化失明)、v2 绝对 Schmitt 门
  (composite 信号上 US-01↔US-03 4% 不可分)。本版据此把复杂度从"新质量
  门"移到真正的残余——结构性删 K + 控制论迟滞,并诚实标注做不到的部分。
- **开放问题——运维已拍板(2026-08-31)**:
  - **冗余下限 `min_pool_size = 4`**。删固定 K 后唯一保留的 size 数字。
  - **检测面约束 = "每个终端所有流量只走一个节点"**(运维原话)。这是
    比"数 fleet IP 总数"更本质的**per-terminal 单出口不变量**,推翻了
    §1-I7 的"限制池总大小"框架:反检测属性来自 per-terminal 单出口,
    不来自小池。含义:
    - `k_max` 作为"检测面上限"的角色**放松**——合格集大一点不伤检测,
      每终端仍只呈现一个 IP。`k_max` 只留作防失控的宽松安全阀。
    - **下限 4 必须硬守**:跌破 per-terminal 的 2-成员门会退化成裸
      `MATCH,us-pool`(load-balance + consistent-hashing),那会**按目的地
      把单终端流量拆到多节点**,直接违反单出口不变量。
    - **fallback 翻动必须阻尼**(实测 BGP_E↔BGP_C on .144):不死也换
      出口 = 违反单出口。primary 的 eligibility 要稳(incumbency + 迟滞),
      且 fallback secondary 应是与刚翻动的那个不同的 IP。
  - **必需可达 = Google + AI 平面**(OpenAI/Anthropic/Cursor)。结合单出口
    不变量:一个终端用一个节点跑全部流量,所以节点须在 **Google 和 AI
    两类上都合格**(worst-leg across 两类),不能只过一类。GitHub/Slack
    等为锦上添花,不作合格硬门。
